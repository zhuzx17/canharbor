# 双向多流压测

该功能实现同一 Runtime 内的 2–8 条命名流、设备集合原子预留、共享配置和全局资源预算，贯通 API、CLI、Web、报告及独立复算。所有验证使用虚拟 CAN、模拟后端及本地服务；不向真实 CAN 设备发送帧。

## 计划与执行

保留原计划字段作为 `primary`；可选 `flows` 是 1–7 条附加流，不重复包含 primary。每条流声明独立的 sender、receivers、CAN ID/标准或扩展格式、run_tag、固定或阶梯负载、判据、计时及 RTT。名称限 1–32 位 ASCII 字母、数字、下划线或连字符；primary 保留。省略 flows 保持原单流计划指纹兼容。

所有流属于同一声明总线，共用 nominal bitrate、接收器 ACK 设置、drain、证据配额、拓扑、RSS 判据及协调租约。不同流可混合 Classic 和 FD；只要一条使用 FD，全部参与通道必须支持共同的 FD data bitrate，物理配置统一。每条流使用独立 tag；所有实际生产者（含 RTT response）的 CAN ID/格式必须唯一，避免把多个生产者的数据误认成同一流。低 ID 表达总线仲裁优先级；软件调度不模拟线上的位仲裁，也不证明真实总线优先级或占用率。

示例：[bidirectional.json](../examples/stress/bidirectional.json)。Web 支持添加反向流及编辑附加流 JSON；开始前必须重新验证并显式授权。计划冻结后不能变更流集合或负载。

一个 Runtime 共享一个压测准入槽，不能通过创建多个 Executor 或 owner 绕过。先编译整个流集合，再一次性预留设备并按稳定顺序配置、获取和启动各唯一通道；同通道只获取一次。所有接收 tap 和发送 lane 准备后释放共同 T0，RTT responder 同样受启动门约束。占用冲突或准备失败关闭整组；启动期停止不会释放部分流。

## 预算与停止

全局预算按所有实际生产者峰值保守相加，包含 RTT responses：最多 20,000 frames/s、每 10 ms 量化批次最多 256 帧、最多 8 个唯一通道。各流精确跟踪内存加 32 MiB 队列预留不得超过 256 MiB；所有流共享证据容量和健康状态，计时与 RX 采样合计最多 2,000 records/s。多流证据分段最小 256 KiB，总段数有界；预检展示每通道、每设备汇总预算。此模型保证资源边界，不保证任意组合达到声明吞吐或承诺各流公平性。

`POST /api/v1/stress/runs/{id}/flows/{name}/stop` 与 `stress stop-flow RUN_ID NAME` 只撤销指定子发送门；既有 owner、来源与 CSRF 校验继续适用。单流停止幂等，已结束流不追加证据；其他流可继续，整组最终为 aborted，不能通过。整组停止关闭父门并传递至所有子门。证据失败、非用户停止的流故障或任何未知提交关闭整组；未知后台 I/O 未结清前保留原设备集合和全局准入槽，不自动重试。接收停止只排空当时已有的有限尾部，避免被仍运行的对向流拖住。

## 报告与证据

报告版本为 8。`group.budget` 保存冻结预算及来源证据派生的设备映射，`group.start_ns` 保存共同启动门，`group.stop_requests` 保存逐流停止时间，`group.flows` 保存各流独立计数、接收质量、阶段、判据、计时和 RTT。父计数按实际物理发送机会汇总，包含 loopback response；子流保留请求/响应分列口径。父报告不虚构合并 receiver 或合并延迟分布。

所有流共享一套有界证据文件和健康状态。`FlowRecord` 为每条流记录命名空间，`FlowEnd` 冻结最终子报告，`FlowStop` 和 `GroupRelease` 记录停止及共同启动门。独立复算逐流重建提交集合、计时匹配和采样接收记录，并校验完整子报告、父汇总、预算、来源及控制证据。子报告使用父 UUID 和流名标识，裁剪重复历史缓存；不能脱离父证据单独宣称 verified。未完整采样的 RX 仍只是在线计数证据，不宣称离线重新捕获全部帧。

服务重启只读恢复：完整证据复算后展示结果，损坏或缺失仅恢复各流可证实下界并标为 interrupted，不创建通道、不续发。多主机协调器检查每台主机全部生产者的 ID/tag 冲突和共享总线配置，并要求支持 v8；跨主机的一程延迟、实际 SSH 故障和真实硬件计量仍需独立门禁。

# 压测停止与证据恢复

这些软件路径全部使用虚拟设备和可控后端验证。没有向真实 CAN 设备发送帧，没有操作已连接的 USB 适配器，也没有挂起主机。24 小时虚拟时钟测试不等于实际运行 24 小时；真实时间长稳测试是独立的发布门禁。

## 停止、故障与租约

报告版本升级为 3，新增 `lifecycle`：停止请求时间、最后尝试/成功提交时间、最后尝试序号、未知在途序号、执行结束时间及结构化终止原因。时间单位为该任务起点的单调时钟纳秒，不是硬件线上时间。

停止请求同步撤销当前子许可，然后唤醒调度器；重复停止不重复推进状态。停止超过 2 秒仍受阻时显示 `stopping_blocked`。已进入不可撤回底层调用的帧仍可能发出，报告不会承诺停止请求后物理总线立即静默。结果不明的帧只记录一次 `unknown`，不自动重试。等待中的调用继续持有设备及执行器预留，不能被替换任务覆盖。

清理操作同时核对租约 generation 与 acquisition epoch。原压测在清理时不能关闭同一租约下重新启动的通道，也不能续约或关闭被另一 owner 接管的通道。设备断开、bus-off、接收溢出、证据队列/磁盘错误均终止任务；恢复设备健康不会恢复发送。服务关闭和已有的睡眠时钟不连续检测继续撤销许可。

状态变化写入单独的 `events-NNNNNN.ndjson` 审计流，带连续 revision；指标和样本仍分别分段。不同类型分段的创建顺序不是全局事件时序，复核器分别验证指标流和审计流。

## 长稳与内存

计划可增加：

```json
"stability": {"max_rss_growth_bytes": 33554432, "warmup_seconds": 60}
```

预热结束后的第一个进程当前 RSS 样本作为基线，记录最大增长；一旦越界即终止，之后内存回落也不会撤销越界事实。配置了监测但平台无法读取 RSS 时，证据不足，不能判为通过。该指标属于整个服务进程，其他并行工作同样会影响 RSS；它不是单个适配器的内存测量。macOS 使用当前进程 Mach task info，Linux 使用 `/proc/self/statm`。Web 支持设置限额和预热时间，并展示监测状态。

历史仍有 120 点上限，证据队列、分段、总磁盘和并发限额沿用 P2。新增 24 小时虚拟时钟测试，检查 86,400 个序号、续租、接收计数和资源释放。实际 24 小时测试显式忽略，需单独执行：

```sh
CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0 \
  cargo test -p canharbor-stress --test p3_faults \
  actual_twenty_four_hour_virtual_soak_with_rss_limit -- --ignored --exact
```

完整服务的 24 小时记录计划见 [soak-24h-virtual.json](../examples/stress/soak-24h-virtual.json)，支持逐帧样本和最终复算。请使用隔离 runtime、启动不带任何硬件选择参数的服务；本次未启动这个长时任务。

这个门禁仅使用内置虚拟后端，目标为 1 帧/秒、24 小时、预热 60 秒后 RSS 最大增长 32 MiB。它不访问物理 CAN。常规回归另有真实时间的短周期测试，同时启用 RSS、逐帧样本、分段和独立复核。

## 服务中断与恢复

启动时恢复记录，不恢复执行。服务被强制终止后，未完成的任务变成 `interrupted`，结论为 `inconclusive`。相同 request ID 仍指向原任务，不能触发第二次发送。

恢复器读取原始分段，逐行验证格式、类型、序号/tag、计数守恒、指标单调性和审计 revision。破损 JSON、缺少换行的尾行、超过 64 KiB 的行或语义错误，均停在该流的有效前缀；后续同类型分段也不能跨越损坏边界。恢复不会截断或覆盖原始 report、checkpoint、identity 或分段。

派生结果写入 `recovery.json` 和必要时的 `recovered.json`。报告附带最多 64 个分段摘要，完整边界在 recovery 文件中。恢复计数标注为下界；没有验证的 checkpoint 不作为权威计数来源。恢复无法证明未知在途帧是否已上总线。

正常报告提交前也执行独立复核。重启后先校验 manifest 文件清单、长度、SHA-256 和计划身份，再复核流与报告。`sample_every=1` 时独立重建每个接收器的位图、重复/乱序和每阶段唯一接收数，必须与报告一致；抽样关闭或 N>1 时仅能校验聚合守恒及实际保存的样本，不能声称复算完整总线流量。

单个无法读取或身份无效的任务进入隔离清单，不隐藏其他健康记录；存在隔离项时阻止新的压测准入，避免绕过占用和磁盘计数。原生 `stress list` 显示 `recovery_issues`。运维应先备份并检查对应 UUID 目录，离线修复或移出证据根目录后重启服务；软件不会自动删除它。浏览器仍按 owner 隔离记录。

## 故障验证范围

自动测试覆盖：排队写入前停止、不可撤回写入、启动调用卡住、重复停止、断连、bus-off、接收溢出、租约释放/接管、同租约重启、服务 fence、24 小时虚拟时钟、RSS 越界和不可用、真实进程 SIGKILL/重启、有效前缀与重复恢复、损坏 report/checkpoint/identity、计数回退、文件篡改，以及写入/刷盘/checkpoint/报告/manifest 提交失败。存储失败使用每个 writer 私有的故障注入，不填满主机磁盘，也不提供远程故障开关。

已有底层许可测试模拟睡眠时钟不连续并验证子许可、续约和 replacement 均不能恢复旧授权。真实 USB 拔插、主机睡眠/唤醒、断电文件系统持久性，以及实际 24 小时运行仍需后续受控硬件或长稳验收，不能据此版本宣称已验证设备可靠性。
